Thought for 2m 19s

Yes — aligned. Do it before cloud assets arrive, but keep it as an architecture gate, not a gameplay milestone. It matches the NexusRealtime rule that games compose runtime + kits + sequences, with ProtoKits as incubation and hosts/renderers as presentation only. 

NexusRealtime-Ideology

 

NexusRealtime-HowTo

Main risk: creating a “docs passed” badge that does not prove the repo actually composes NexusRealtime kits. The validator must fail on code drift, not just missing markdown.

Other risks:

stale anchors when node_modules docs update;

validator coupling to exact README prose instead of stable principles;

duplicating ProtoKit rules instead of validating the local GoldRush kit contracts;

.agent/goal.md becoming the source of truth instead of a tracked projection of repo state;

cloud asset delay hiding missing thin-slice/headless-test work.

Required manifest fields:

manifestVersion

sourceDocs[]: path, package name, version/hash, required anchors

principles[]: deterministic tick, kits own behavior, ProtoKits incubate, data contracts, renderer-agnostic/headless validation, no DOM/Canvas/Three in non-adapter kits

goldRushMappings[]: principle → local file/gate/test

kitGates[]: VERSION, createXKit, resources, events, systems, requires/provides, init/install/reset/snapshot/tests

forbiddenPatterns[]: DOM/Canvas/Three/browser globals inside domain kits

goalSync: path to ME/GoldRush/.agent/goal.md, required goal IDs/status markers

validatorOutputs: pass/fail, warnings, source hash diff, missing anchors, CI command

Validation edge cases:

docs exist but package import path is wrong;

source doc hash changed but anchors still semantically valid;

renderer adapter legitimately uses Canvas/Three and must be exempted by kit type;

tests exist but are browser-only, not headless;

requires/provides tokens exist but do not match installed kit composition;

custom GoldRush kit has VERSION/create factory but no reset/snapshot path;

.agent/goal.md says aligned while manifest or tests fail;

vendored docs differ from lockfile package version.

Better next step: implement the manifest plus one executable smoke validator that composes NexusRealtime + ProtoKits + one GoldRush custom kit headlessly, ticks once, inspects resources/events, and fails if any non-adapter kit touches host/renderer APIs. That turns “source-doc alignment” into a real NexusRealtime gate.
