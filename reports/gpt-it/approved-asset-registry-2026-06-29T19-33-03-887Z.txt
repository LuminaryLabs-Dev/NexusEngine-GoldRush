Thought for 2m 18s

Yes — this is the right next step before cloud assets arrive.

Why

It creates the trust boundary now: placeholders remain default, approved assets become an explicit overlay only after provenance, hashes, approval, and safe runtime path exist.

It matches the NexusRealtime split: content/data can configure presentation, while renderer/runtime should not ingest raw cloud sources or own asset-validation logic.

It gives you a clean “empty pending import passes / unsafe approved import fails” gate, which is exactly what you need before real assets land. 

NexusRealtime-Ideology

Risks

Schema drift: goldrushApprovedAssets.js could diverge from goldrush-cloud-transfer-handoff.json unless field names and hash algorithms are fixed now.

False approval: records could look approved without actual local asset existence unless runtimePath is later checked against copied files.

Path escape: ../, URL-encoded traversal, backslashes, double slashes, %2e, symlinks, or case variants could bypass naive string checks.

Premature replacement: overlay logic could replace a placeholder if only runtimePath exists but provenance or hashes are missing.

Slot mismatch: an approved asset could target a nonexistent, duplicate, deprecated, or wrong-type slot.

Hash ambiguity: sourceHash and outputHash need declared algorithm, encoding, and canonical byte basis.

Browser leakage: approved overlay must not expose raw cloud paths, signed URLs, local absolute paths, or quarantine/sanitization internals to the client.

Required fields

slotId or equivalent registry target.

sourceJobId

sourcePath

sourceHash

outputHash

provenance

approvalId

runtimePath

Strongly recommended: assetType, mimeType, hashAlgorithm, approvedAt, approvedBy or approval authority, license/rights, dimensions/duration where relevant, and notes/rejectionReason for auditability.

Validation edge cases

Allow empty approved list and pending placeholder-only state.

Reject missing, null, empty-string, or whitespace-only required fields.

Reject runtimePath unless it is relative and starts with exactly assets/.

Reject public/assets/...; runtime code should reference assets/..., not the filesystem/public prefix.

Reject raw/, sanitized/, quarantine/ anywhere in normalized path segments.

Reject http://, https://, //cdn..., data:, blob:, file:, absolute /..., Windows C:\..., backslashes, .., encoded traversal, and control characters.

Reject querystrings/fragments in runtimePath.

Reject duplicate slotId, duplicate approvalId, duplicate runtimePath unless explicitly allowed.

Reject output hash equal to empty, placeholder hash, malformed hash, or wrong algorithm length.

Reject approved records targeting unknown slot IDs or incompatible presentation/runtime slot types.

Reject records where sourceHash exists but sourceJobId does not match the handoff manifest later.

Later, after local copy: fail if the file under public/assets/... is missing or its computed outputHash does not match.

Alignment with final goal

Aligned. This keeps Gold Rush playable with placeholders now, blocks unsafe cloud/raw assets from the browser, and prepares a deterministic promotion path from “handoff manifest” to “approved runtime asset.”

Best next implementation shape: goldrushApprovedAssets.js exports empty approvedAssets = [] plus validateGoldrushApprovedAssets() and applyGoldrushApprovedOverlay(baseRegistry, approvedAssets), with tests proving empty pass and unsafe approved records fail.
