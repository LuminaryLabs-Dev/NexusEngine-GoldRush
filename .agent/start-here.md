## Current Operating Summary

- Build a high-fidelity wild-west extraction battle royale in this repo only.
- Follow `AGENTS.md` and `.agent/agent-it-operating-contract.md` as the durable agent entry contract.
- Follow the strict full-version rebuild loop before implementation.
- The newest version is the default work target for every turn.
- A version is a complete rebuild attempt from the ground up, not a patch on the previous app.
- Each turn either improves the newest version or increments only when the newest version is stuck, flawed, overcomplicated, fake, or carrying bad assumptions.
- Carry forward only validated parts, validated contracts, current lessons, current design docs, and current roadmap goals.
- Do not create `v0.0.2` until `v0.0.1` has a clear continue-or-increment decision.
- Use NexusRealtime-style domain kits as the architecture, not ad hoc renderer/app logic.
- Keep generic reusable kits in the local incubator until they are proven promotable.
- Keep GoldRush-specific orchestration in GoldRush custom kits.
- Treat legacy Unity assets/audio as copied evidence until they pass sanitation, license, human review, and approved-runtime promotion gates.
- Use local/public screenshots for regular state audits; use video only for camera, movement, pulsing, train, and interaction timing issues.
- Update `.agent/change-log.md` after meaningful agent workspace or repo changes.

## First Question For Any New Work

What is the newest version, what does its audit say, and should this turn continue it or increment?
