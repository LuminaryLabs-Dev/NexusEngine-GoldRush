# Reward Loop Contract

Status: active docs-only

## Purpose

Define the minimum reward loop GoldRush should prove before claiming replayability.

## Loop

```txt
spot value
-> choose route
-> mine or loot
-> carry risk
-> survive pressure
-> cash out
-> score receipts
-> replay lesson
-> optional unlock/progress
-> run again
```

## Required Data

- source id and source type.
- value amount and value tier.
- carry burden and risk modifier.
- cashout state and contest state.
- score calculation version.
- reward eligibility by mode.
- replay lesson summary.
- next-run suggestion.

## Hard Rule

No reward can become persistent unless mode eligibility, source receipt, cashout receipt, progression rule, and release ruleset version all agree.
