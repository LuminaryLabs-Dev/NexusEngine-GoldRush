# Source Reference Matrix

Status: active docs-only

## Purpose

Connect each economy/retention system to a current external reference signal. These references are not instructions to copy another game; they expose missing product surfaces GoldRush must answer in its own western extraction language.

| System | Reference signal | GoldRush implication |
| 01 Run Value Ladder | Apex Legends official game modes | PUBG uses land/loot/survive as a simple value arc; GoldRush needs mine/carry/extract/survive as its equivalent. |
| 02 Gold Source And Sink Model | PUBG official game overview | Apex distinguishes modes that progress XP or stats from modes that do not; GoldRush must tag reward eligibility per mode. |
| 03 Loot And Tool Table | Fortnite ranked and team fill support | Apex Wildcard simplifies looting while Core keeps richer systems; GoldRush can support simple practice tables before full match tables. |
| 04 Claim Contract Objectives | Fortnite team fill support | Battle royale products use clear mode and objective framing; GoldRush needs claim contracts to make each run legible. |
| 05 Risk Reward Tiers | GitHub game engine collection | PUBG care package smoke communicates reward and danger; GoldRush needs equivalent world language for rich claims. |
| 06 Extraction Stakes And Loss | GitHub JavaScript game engine collection | Extraction games depend on loss pressure; Apex practice modes also show why staging modes must not overclaim stakes. |
| 07 Final Rush Pressure Economy | Apex Legends official game modes | PUBG blue zone forces movement; GoldRush final rush should force cashout and contest decisions. |
| 08 Squad Role And Share Rules | PUBG official game overview | Fortnite exposes Solo, Duo, Trio, and Squad choices; GoldRush group type needs equally clear player-facing meaning. |
| 09 Bot Fill Reward Boundary | Fortnite ranked and team fill support | Apex Bot Royale allows XP/challenges but not badges/stats; GoldRush needs explicit eligibility boundaries. |
| 10 Replay Lesson Loop | Fortnite team fill support | Modern battle royale modes use results, challenges, and mode labels to create return loops; GoldRush should make each run teachable. |
| 11 Progression Without Grind | GitHub game engine collection | Apex distinguishes mode progression eligibility; GoldRush needs progression only after core loop proof stays fun. |
| 12 Challenge And Contract Rotation | GitHub JavaScript game engine collection | Apex and other battle royales use challenges and limited-time modes; GoldRush should plan this as optional live-ops, not core MVP. |
| 13 Cosmetic And Identity Boundary | Apex Legends official game modes | Fortnite exposes team and mode choices around identity; GoldRush should make prospector identity clear but not mix it with power. |
| 14 Tuning And Telemetry Ledger | PUBG official game overview | Game-engine-style workflows need tooling and repeatable data; GoldRush should track balance as data, not scattered constants. |
| 15 Fairness And Abuse Boundary | Fortnite ranked and team fill support | Competitive and ranked modes in battle royale products require stronger integrity than practice modes; GoldRush must label the boundary. |
| 16 Release Versioned Economy Policy | Fortnite team fill support | Long-running battle royale products evolve through modes, events, and patches; GoldRush needs versioned economy from the start. |

## Source Links

- Apex Legends official game modes: https://help.ea.com/en/articles/apex-legends/game-modes/
  - Signal: Apex separates competitive, relaxed, bot, private, training, and firing-range contexts. It also distinguishes progression-safe and non-progression-safe modes. GoldRush needs the same separation for practice, staging, simulated 60-player, public proof, and future live match claims.
- PUBG official game overview: https://pubg.com/en/game-info/overview
  - Signal: PUBG frames battle royale around land, loot, survive, shrinking zone pressure, care package risk, vehicles, training, and solo/duo/squad modes. GoldRush should translate that into train entry, claim route selection, gold/tool/resource economy, final-rush pressure, extraction risk, and staging practice.
- Fortnite ranked and team fill support: https://www.epicgames.com/help/c-202300000001636/c-202300000001721/how-to-toggle-ranked-and-team-fill-modes-in-fortnite-a202300000014894
  - Signal: Fortnite exposes mode, ranked toggle, fill, and team-size options at the player-facing layer. GoldRush needs party size, practice, fill/bot, and competitive-readiness choices to be product contracts, not hidden debug toggles.
- Fortnite team fill support: https://www.epicgames.com/help/c-202300000001636/c-202300000001721/unable-to-find-teammates-while-playing-in-duos-trios-or-squad-in-battle-royale-and-zero-build-modes-in-fortnite-a202300000014690
  - Signal: Team fill is a simple player-facing switch with large match-quality implications. GoldRush should separate invited party, bot fill, squad fill, and no-fill staging behavior in data and proof.
- GitHub game engine collection: https://github.com/collections/game-engines
  - Signal: The collection highlights broad game-framework surfaces such as multi-platform runtime, rendering, tools, and content systems. GoldRush should not become a general engine, but economy and retention still need kit-owned data, validation, tuning, and deploy proof.
- GitHub JavaScript game engine collection: https://github.com/collections/javascript-game-engines
  - Signal: The JavaScript collection highlights browser game runtime concerns: rendering, physics, WebGL/WebGPU, glTF, and web delivery. GoldRush economy/progression data must stay browser-safe, serializable, and proofable in local/public builds.
