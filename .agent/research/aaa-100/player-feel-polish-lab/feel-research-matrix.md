# Feel Research Matrix

Status: active docs-only

## Purpose

Connect each feel axis to an external reference signal. These references do not define GoldRush directly; they expose missing product surfaces that a serious battle-royale/extraction game usually needs.

| Axis | Reference signal | GoldRush implication |
| 01 Camera Mouse Look Feel | Apex Legends official game modes | Apex splits competitive and relaxed modes, so GoldRush camera proof needs both high-pressure combat and relaxed training contexts. |
| 02 Camera Authority Stability | PUBG official game overview | Battle royale modes need fast context shifts; authority resets are required at every scene transition. |
| 03 WASD Locomotion Feel | GitHub game engine collection | PUBG emphasizes landing, looting, vehicles, and moving under pressure; GoldRush must make traversal itself legible before adding scale. |
| 04 Terrain Footing Grounding Feel | GitHub JavaScript game engine collection | The map-source plan should derive render and physics from the same source revision so footing can stay trustworthy. |
| 05 Character Rig Body Readability | Apex Legends official game modes | Apex and PUBG both use strong avatar readability; GoldRush needs equivalent silhouette clarity even with toon assets. |
| 06 Locomotion Animation Blend | PUBG official game overview | Training/practice modes in reference games exist partly to let players learn movement feel without match pressure. |
| 07 Mining Hold Tactility | GitHub game engine collection | PUBG supply drops use visible risk signals; GoldRush mining should similarly broadcast reward and danger. |
| 08 Cargo Weight Feedback | GitHub JavaScript game engine collection | Extraction play works when value creates vulnerability; GoldRush must show value on the body and in the world. |
| 09 Resource Object Readability | Apex Legends official game modes | Browser games need instancing/performance, but player-facing resource forms still need authored visual hierarchy. |
| 10 Cashout Tension Feedback | PUBG official game overview | PUBG uses supply drops and blue zone to combine visible reward and danger; GoldRush cashout needs the same clarity. |
| 11 Threat Telegraph Readability | GitHub game engine collection | Apex Bot Royale and PUBG training imply staged pressure matters; GoldRush should support relaxed threat learning before full pressure. |
| 12 Cover And Combat Counterplay | GitHub JavaScript game engine collection | Battle royale maps depend on terrain and object placement; GoldRush cover must derive from authored map/source masks. |
| 13 Weapon Hit Feedback | Apex Legends official game modes | Apex mode variants simplify or expand systems; GoldRush can start with simple weapons but must still expose full feedback contract. |
| 14 Audio Cue Layering | PUBG official game overview | Reference games use audio as information; GoldRush should treat audio as a domain service, not decoration. |
| 15 VFX And Diegetic Cues | GitHub game engine collection | PUBG and Apex rely on mode-specific player information; GoldRush should provide information diegetically when possible. |
| 16 Results Payoff Readability | GitHub JavaScript game engine collection | Apex separates ranked and relaxed progression; GoldRush results should separate practice, staging, and real match claims. |
| 17 Accessibility And Control Comfort | Apex Legends official game modes | Training modes in battle royale products acknowledge player learning variance; GoldRush needs comfort settings before broad testing. |
| 18 Local Public Human View Proof | PUBG official game overview | GitHub engine collections imply mature tooling and multi-platform proof; GoldRush needs browser deployment proof as a first-class kit concern. |

## Source Links

- Apex Legends official game modes: https://help.ea.com/en/articles/apex-legends/game-modes/
  - Signal: Separates competitive Core from relaxed Freestyle, includes Bot Royale Evolved, private matches up to 60 players, Training, and Firing Range. GoldRush should likewise separate public claims, staging, bot fill, and practice proof instead of treating one proof as all modes.
- PUBG official game overview: https://pubg.com/en/game-info/overview
  - Signal: Frames battle royale as land, loot, survive with 100-player scale, shrinking space pressure, supply risk, vehicles, solo/duo/squad modes, and training. GoldRush needs readable phase language, route stakes, and practice surfaces.
- GitHub game engine collection: https://github.com/collections/game-engines
  - Signal: The collection highlights engines as multi-platform game frameworks. GoldRush should not become a general engine, but its local kits still need engine-like surfaces: render, input, audio, physics, tooling, validation, content, and release gates.
- GitHub JavaScript game engine collection: https://github.com/collections/javascript-game-engines
  - Signal: Browser games still need mature runtime concerns: rendering, interaction, asset pipelines, and proof. GoldRush should keep those as local kits and validators rather than renderer-only one-offs.
