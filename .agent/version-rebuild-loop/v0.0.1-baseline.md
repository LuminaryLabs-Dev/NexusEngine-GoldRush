# v0.0.1 Baseline

Status: active baseline audit

## Purpose

Treat the current GoldRush prototype as `v0.0.1`, then split it into working, partial, fake/helper-only, broken, missing, stale, and bad-assumption parts before any later version inherits behavior.

## Known Working Candidate Areas

These are candidates only until each has current proof attached:

- NexusRealtime-style domain kit registry
- validation command stack
- public proof conventions
- title/lobby/train/run scene scaffold
- player-driven mine/carry/cashout/results scaffolding
- camera and ground stability proof harnesses
- asset approval boundary validators
- report sanitization validator

## Known Non-Final Areas

- authored terrain source is not runtime truth yet
- terrain visual fidelity is not AAA map quality
- assets are not fully approved runtime content
- combat is structural, not production combat
- bot staging is not final single-player staging
- simulated topology is not live 60-player readiness
- player feel and animation are not final
- public proof is not a full final-game completion claim

## Current First Task

Audit `v0.0.1` before creating any later version.

The audit must decide:

- continue `v0.0.1` because it is still a sound base for the next atomic slice
- increment to `v0.0.2` because `v0.0.1` is stuck, structurally wrong, overcomplicated, fake, stale, or carrying bad assumptions

Do not create `v0.0.2` until this decision is explicit.

## Baseline Decision

Current decision: continue `v0.0.1` with limits.

Decision packet: `v0.0.1-audit.md`.

Do not carry the whole `v0.0.1` app into any future version.

Carry only:

- validated proof infrastructure
- validated kit contracts
- validated source/asset safety gates
- validated player-loop scaffolding where current proof matches the claim
- current lessons
- current design docs
- current roadmap goals

Everything else must be re-proven or rebuilt through the version loop.
