# v0.0.2 Plan

Status: active version plan

## Purpose

Create a parallel kit-by-kit rebuild layer that uses `v0.0.1` only as validated reference and lessons.

## Architecture Rule

```txt
domain = broad system area
subdomain = focused capability inside that area
kit = one owned, testable unit inside a subdomain
```

## Version Scope

- Create top-level kits under `src/kits/v0.0.2/<domain>/<subdomain>/`.
- Use `src/kits/v0.0.2/registry.js` as the source of truth.
- Use grouped proof pages under `public/proof/v0.0.2/`.
- Expose a read-only `window.GoldRushHost.getState().v002` surface.
- Keep existing `engine.n.goldrush*` APIs intact during the scaffold phase.
- Treat FBX/OBJ/BLEND as source-only intake through the new content domain; promote GLB only after review and runtime-gate proof.

## Boundary Rules

- Behavior kits are system controllers that decide intent from an outside perspective.
- Animation and narrow control kits are execution kits that apply descriptors.
- Render kits consume descriptors and never own gameplay truth.
- GoldRush kits compose reusable kits into game-specific rules and are not promotable as-is.
- Proof pages validate grouped domains, not one page per small kit.

## Slice Order

1. Registry, metadata, kit folders, grouped proof pages, validators, and `v002` state surface.
2. Source-only content intake for FBX/OBJ/BLEND provenance, inventory, and conversion requests.
3. Runtime and scene proof integration.
4. World/physics terrain source handoff from validated `v0.0.1` terrain contracts.
5. Control/behavior/animation controller split.
6. Render descriptors consuming kit snapshots.
7. Gameplay mine/carry/cashout loop.
8. Train/lobby/title sequence.
9. Match/results/replay.
10. Network staging and simulator proof.
11. Public proof refresh.

## Current Proven Slice

- World/physics terrain-source handoff is implemented as deterministic recipe `goldrush-seeded-world-r1` for a 10,240x10,240-meter Gold Rush world.
- The world is divided into 128-meter canonical tiles; runtime selection produces four camera-centered rings at 4/8/16/32-meter detail, and only the near ring contributes to the local collision window.
- `GOLD_RUSH_GREYBOX_LAYOUT` remains the authored origin region and owns the basin, mine and town shelves, widened terrain route network, canyon perimeter, landmarks, and blocked areas inside the shared seeded height source.
- Deterministic rock, scrub, and cactus descriptors use stable tile-derived IDs and follow tile lifecycle; terrain geometry rebuilds only after the focus crosses a tile boundary.
- Renderer, collider, route grounding, landmark placement, and feature placement consume one world-coordinate height source; no second visible terrain sheet or full-world collider is created.
- Camera-relative movement now uses one canonical look transform: W/S follow planar look forward, A/D follow rendered screen-right, and both loading/run cameras aim directly along the same yaw and pitch.
- Five fixed-profile headless captures prove the active terrain across all four LOD rings, and the final exact Pages-route browser proof completes title, boarding, mining, cash-out, and results on the production build.

## First Slice Acceptance

- Every v0.0.2 kit has a domain, subdomain, `domainPath`, reset, snapshot, validator, and proof group.
- No individual small kit gets its own HTML page by default.
- `GoldRushHost.getState().v002` exposes version, domains, kits, proof groups, snapshots, events, and validation.
- All v0.0.2 validators pass.
- `npm run validate` and `npm run build` pass.
